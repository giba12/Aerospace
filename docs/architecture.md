# Architecture (as built at M5)

> This is a small educational simulation, not flight software, and it makes no claim of flight qualification, operational fidelity or real sensor fusion (SYS-006).

The design of record is [systems-engineering-baseline.md](systems-engineering-baseline.md)
sections 7 (design) and 8 (interfaces). This page records only what the code does today and
the choices made while building the skeleton (DOC-002). Update it whenever either changes.

## What exists

| Piece | State |
|---|---|
| `Dynamics` (`propagate`) | Real: explicit Euler with optional constant acceleration (`--accel`) |
| `NoisySensor` | Real: position + sigma x z every M steps, z a standard-normal draw from a seeded `std::mt19937_64`; sigma 0 is exact |
| `KalmanEstimator` (+ `kalman_predict` / `kalman_update`) | Real: linear Kalman filter, Joseph-form update; the maths is two pure functions in `kalman.hpp`, the class is the state machine |
| `Runner` | Real: implements the call order of baseline 7.4 exactly |
| `CsvRecorder` | Real: exact header, 17 digits, empty = missing, atomic rename |
| CLI | Real subset: the fourteen flags in use (`--accel` added in M1; `--sigma`, `--seed` in M2; `--est-q`, `--est-r`, `--est-p0-pos`, `--est-p0-vel` in M3), exit codes 0/1/2 |
| Sidecar JSON (IF-08) | Real: `<out>.config.json`, 16 flat keys, schema_version 1; since M3 the four estimator keys hold the filter's settings |
| `tools/check_budget.py` | Fails if the suite took longer than 30 s (NFR-006) |
| `analyze.py` | Header and sidecar checks incl. `schema_version` (ANA-001), RMSE, +/-2 sigma coverage, `metrics.json` (baseline 8.7), and the labelled three-panel plot |
| `kalman_oracle.py` | Independent re-computation of the `est_*` columns in 60-digit decimal arithmetic (VAL-04, DD-012) |
| `seed_sets.py` (in `python/`) | The tuning and held-out seed sets (TST-012) |
| `ensemble.py` | Runs `sim` over a seed set and reports VAL-02 and VAL-03; used by the acceptance tests and by `docs/VALIDATION.md` |

## Decisions made while scaffolding

| # | Decision | Alternatives | Why |
|---|---|---|---|
| S-1 | **OI-01:** GoogleTest v1.17.0 via `FetchContent` with a URL and SHA-256 hash | System package; git tag; vendoring | Pinned by content, so the tag cannot move (NFR-009); identical on laptop and CI. **Awaiting owner confirmation** |
| S-2 | The repository root is `aerospace/`; `docs/` was already there | A `sensor-sim/` subfolder; the empty `Project/` folder | Matches the layout in baseline 7.8 with no nesting. `Project/` is left untouched |
| S-3 | `cli_main` lives in `simcore` (`cli.hpp`); `main.cpp` makes one call | Flag parsing in `main.cpp` | Lets tests call the CLI directly (TST-001, DD-001). Adds one header beyond baseline 7.8 |
| S-4 | Flag table drives both parsing and `--help` | Separate help string | The documentation cannot drift from the parser (CFG-001) |
| S-5 | `junit.gtest` re-runs the whole suite once, in addition to per-test discovery | One CTest entry for the binary; CTest's own JUnit output | Per-test listing satisfies TST-003; gtest's XML carries the requirement tags that CTest's does not |
| S-6 | `-Werror` defaults ON | Default OFF, ON only in CI | Baseline NFR-001, and the toolchain is pinned. Easy to turn off locally |
| S-7 | Traceability gate: unknown IDs and orphan tests fail now; uncovered Musts fail only with `--require-coverage` | Gate on from day one | At M0 most Musts are future work; baseline 6.7 turns coverage on at M5 |
| S-8 | Registry `docs/requirements.csv` generated from baseline 6.5 | Parse the markdown at run time | A CSV is stable to parse. Cost: two sources until REQ v0.2 is issued |
| S-9 | `tests/python/` added for unit tests of the Python tools | Put them in `tests/system/` | They are not system tests. One directory beyond baseline 7.8 |
| S-10 | `analyze.py` uses the standard library only; `requirements.txt` pins pytest only | Add pandas/matplotlib now | Nothing imports them yet; add them, pinned, in M4 |
| S-11 | `tools/trace.py` renamed `tools/req_trace.py` | Keep the name | `import trace` shadowed the standard-library `trace` module and only worked because `pytest.ini` puts `tools/` first on the path |
| S-12 | `steps` is bounded above by `kMaxSteps = 100000` in `config.hpp`, checked in `DynamicsConfig::validate()`; `--help` text is built from the constant | No limit; limit only in the CLI | A typo such as `--steps 1000000000000` would run for hours and fill the disk. Checking in `validate()` makes the runner enforce it too (SIM-006). The baseline §8.3 flag table still says "integer ≥ 0" and should be updated at the next baseline revision |
| S-13 | `analyze.py` converts every numeric cell through one helper that raises `CsvFormatError` naming the data row, step and column, and rejects empty, non-numeric and non-finite cells, ragged rows and non-UTF-8 files | Let `float()` raise | A bad file now produces `analyze: error: ...` and exit 1 instead of a traceback |
| S-14 | Euler order is fixed: position uses the OLD velocity, then velocity is updated. The error against exact kinematics is `a·t·dt/2`, tested at every step and against VV-SIM-01 (5995.0 m, 110.0 m/s) | Semi-implicit Euler (position uses the NEW velocity); RK4; closed form | The baseline names explicit Euler (DD-006) and VV-SIM-01 fixes the numbers. Semi-implicit would give 6005.0 m and silently change the documented bound; a mutation test confirmed the tests catch that. RK4 and the closed form are exact for constant acceleration but would hide the error bound SIM-004 asks us to document |
| S-15 | Position tolerance in tests is `position_tol_m(cfg, k) = max(1e-9 m, 2·k·u·X)` (CR-24), shared via `tests/support/`. Test helpers `make_cfg`, `walk_truth`, `time_s` are reusable by later milestones | Fixed 1e-9 m everywhere; per-test tolerances; a separate numeric-accuracy requirement | A fixed tolerance cannot be met for long runs. One shared definition keeps tests and baseline §6.3 identical. See `docs/change-requests/CR-24-position-rounding-allowance.md` |
| S-16 | The sensor draws a standard normal and multiplies by sigma, instead of drawing from N(0, sigma^2) | Construct the distribution with sigma | sigma = 0 is exact with no special case (SEN-003), and the same seed with a different sigma gives the same noise pattern scaled, so noise experiments are directly comparable |
| S-17 | `AtomicFile` (write to `.tmp`, rename on commit, delete on failure) and `format_double` extracted to `output_util`, shared by the CSV recorder and the sidecar | Copy the logic into the sidecar writer | Two users of the same safety-critical logic; one tested implementation (OUT-004, OUT-005) |
| S-18 | Sidecar is staged before the run and committed after the CSV; if its rename fails, the committed CSV is removed | Write it after the run; write it before the CSV | A bad sidecar path fails early, and exit 1 still promises no CSV left behind (IF-02) |
| S-19 | Sidecar estimator keys are `null` at M2 (CR-25) | Omit them; add `EstimatorConfig` and `--est-*` flags now | Keeps one key set for schema_version 1 across M2 and M3 without flags that a stand-in would ignore |
| S-20 | `--seed` uses a dedicated unsigned parser that rejects a leading minus sign | `strtoull` alone | `strtoull("-1")` silently wraps to 2^64 - 1 |
| S-21 | `source_revision` comes from `git describe --always --dirty` at CMake configure time, `null` without git | Run git at build time or at run time | Cheap and deterministic per build; it can be stale after a later commit until cmake is re-run |
| S-22 | The filter maths is two pure functions (`kalman_predict`, `kalman_update`) on a `KalmanState`; `KalmanEstimator` is a thin state machine around them | Put the maths inside the class | VV-EST-01 starts from a hand-picked belief `[0, 10]` that initialization can never produce; the Python cross-check (DD-012) mirrors the same two functions. Adds `kalman.hpp` and `kalman.cpp` beyond baseline 7.8 |
| S-23 | `PassthroughEstimator` was removed, not kept | Keep it as a baseline for comparison | Baseline 7.5 describes the raw sensor as the comparison; keeping dead code that tests no longer use invites confusion |
| S-24 | The `--est-*` flags and real sidecar values arrive together with the filter (M3) | Add them in M2 (rejected in CR-25) | Honours S-19: no flag exists that something ignores. Closes the `null` placeholder from CR-25 |
| S-25 | A reading older than the last accepted one is rejected; an equal timestamp is accepted. The "last reading" time is tracked separately from the filter's own clock | Compare against the filter clock | The filter clock is advanced by `+= dt` and drifts by rounding from the runner's `k * dt` timestamps; comparing against it would reject valid readings |
| S-26 | The independent oracle computes in 60-digit `decimal` arithmetic on the exact values of the doubles the C++ got, with a different formulation (scalar, expanded predict, short update form) | An oracle in doubles; a port of the C++ | A double-precision oracle was itself wrong after 100,000 steps without a reading (error 4.9e-7 against 9e-16 for the C++ Joseph form). An oracle must be more accurate than what it checks. Costs 6 to 8 s for a 100,000-step run, so the tests use at most 20,000 steps. CR-26 |
| S-27 | Oracle tolerance is `max(1e-9, 2·k·u·|value|)`, the CR-24 form. **Proposed, not yet approved**; the baseline row is unchanged | Fixed 1e-9 | A fixed value is below the spacing of doubles for large variances. Worst case uses 23 % of the allowance. CR-26 |
| S-28 | Two disjoint seed sets live in `python/seed_sets.py` (moved from `tests/` in M4 so the ensemble tool can import them) (200 tuning, 50 held-out). The acceptance tests import only the held-out set, and a test checks both that and the disjointness | One seed list; a convention | Makes "performs well on unseen data" mechanically checkable (TST-012, CR-06, R-05). Thresholds (0.75, 0.90) were re-measured on the tuning set only: ratio 0.317 to 0.576, pooled coverage 0.975 |
| S-29 | `analyze.py` returns `n_within_2sigma` as well as the fraction | The fraction only | Pooled coverage across seeds needs the counts, not an average of fractions (EST-012) |
| S-30 | `analyze.py` REQUIRES the sidecar and rejects a missing one, an unknown `schema_version`, a missing key, or a row count that is not `steps + 1` | Treat the sidecar as optional | The format version lives only in the sidecar (baseline 8.9), so without it a CSV cannot be recognised. The row-count check catches a CSV paired with another run's settings. Hand-made CSVs in tests now need a sidecar |
| S-31 | `metrics.json` has exactly the eight keys of baseline 8.7; `n_within_2sigma` stays in the Python result and on screen but not in the file. `improvement_ratio` is `null` when the raw RMSE is 0 | Add the count to the file; write NaN | Adding a key is an interface change needing a baseline edit (8.9); JSON has no NaN and OUT-005's "never nan" rule applies to every output |
| S-32 | matplotlib is imported only inside `make_figure`, via `Figure` and not `pyplot`, and every output path is checked before any slow work | Import at the top; use `pyplot` | Metrics-only use and most unit tests need no plotting library and no global GUI state; a bad path fails in milliseconds instead of after the 2-3 s figure |
| S-33 | matplotlib is pinned at 3.10.8, not 3.10.0 | 3.10.0 | 3.10.0 triggers 100+ deprecation warnings against the newest pyparsing that pip resolves; 3.10.8 is quiet and in the same minor series. A pinned set should not teach people to ignore warnings |
| S-34 | `ensemble.py` owns the thresholds (0.75, 0.90) and the pass/fail logic; the acceptance tests import it; `--max-seeds` exists for quick tests and the report says "partial" when used | Duplicate the logic in the tests; always run all seeds in tests | One definition of "pass". 200-seed tests took the suite from 10 s to 48 s against the 30 s budget (NFR-006); a partial run cannot masquerade as acceptance |
| S-35 | `docs/VALIDATION.md` is built from the tool's JSON output, and the held-out and scenario results are kept separate (held-out = acceptance; scenarios run on the tuning seeds, report only) | Hand-type the numbers; run scenarios on the held-out seeds | No transcription errors, and no scenario exploration can contaminate the held-out set (TST-012) |
| S-36 | `SIM_SANITIZE` adds `-fsanitize=address,undefined -fno-sanitize-recover=all` before any target is created, so the fetched test framework is built the same way; it cannot be combined with `SIM_COVERAGE`; CI has its own job and the 30 s budget does not apply to it | Sanitizer flags only on first-party targets; let findings print and continue | A mixed build can hide a finding at the boundary, and a finding that only prints lets a test pass over it. Checked live: a planted use-after-free was caught by ASan, a planted overflow and an out-of-bounds index by UBSan. The sanitized suite takes about twice as long |
| S-37 | `SIM_COVERAGE` plus a `coverage` target using pinned `gcovr` with `--exclude-throw-branches`; the report is uploaded and never gates (no `--fail-under`, enforced by a test) | A gate at 90 %; `lcov` | NFR-008 says "a goal reported in CI, not a gate". Excluding compiler-generated exception edges moves branch coverage from 59.6 % to 85.3 % locally; both are stated. Lines 94.0 % locally and 94.5 % on CI (cause of the difference not investigated), functions 100 % |
| S-38 | The 12 Musts that had no test are closed by 3 kinds of check: behaviour (ctest -N lists every test, JUnit parses, unknown framework refused, no writable global data), the new tools with unit tests (budget, fail-closed traceability), and **automated inspection** of build files, CI workflow and docs. The inspection tests say so in their docstring | Mark them verified by review only; write nothing | The baseline's verification matrix plans I and D for these. Automating the inspection stops drift, but it is weaker than a behaviour test and the README says so |
| S-39 | `tools/check_budget.py` sums the `time` of every JUnit test case and fails over 30 s; CI runs it on the normal GCC and Clang builds only | Wrap `ctest` in `timeout 30`; per-test timeouts | One number for the whole suite including the seed ensembles (NFR-006), with a message and a unit test. Not applied to sanitizer or coverage builds, which are slower by design |
| S-40 | `req_trace.py` fails with a clear message on a missing, unparseable or empty JUnit file | Let the traceback propagate | It already failed closed (exit 1) but with a raw traceback; an empty report would also have made the gate pass vacuously |
| S-41 | CI passes `--require-coverage`: the build fails if any Must requirement has no passing test | Leave the gate off until release | M5's exit criterion (baseline 6.7); the registry has 61 Musts and all are covered |
| S-42 | NFR-003 ("no hidden global state") is checked on the compiled library: `nm` must find exactly two writable data symbols, the flag table and the CSV header pointer, both constants | Extend the text grep for `rand(` and `time(` | Objective and hard to evade; any new mutable global fails it and must be justified in the allow-list. Compiler-generated `typeinfo` and `vtable` entries and sanitizer or coverage symbols are excluded by name |
| S-43 | The Catch2 adapter (TST-010, Could) is not built | Build it | It would mean rewriting about 50 tests whose logic is inline in the GoogleTest files, for a stretch goal. TST-002 is still verified by refusing an unknown adapter and by keeping framework names out of everything except `tests/` |
| S-44 | A one-line SYS-006 banner was added to the docs that lacked it (architecture, validation, file map, worksheet, code report); the requirement documents are exempt from the overclaim scan | Test only the README | SYS-006 says all documentation. The scan looks at whole paragraphs because a sentence can wrap, and exempts the five documents that define or discuss the requirement itself |
| S-45 | One `Dockerfile` at the repository root, a single stage: install g++, cmake, ninja and python, create the pinned venv, build, **run the whole test suite**, and default to running the reference scenario with analysis and the oracle | Build in one image and ship a slim runtime image; build only, no tests | The purpose is a clean-room check (SYS-001 / VAL-01), so the tests must run in the image: an image that exists is one whose tests passed. A second stage would save space nobody needs for a local demo. `--build-arg RUN_TESTS=0` skips the tests |
| S-46 | The base image is pinned by registry digest (`ubuntu:24.04@sha256:78d4...`), apt packages are not individually pinned | Pin every apt version; use the tag alone | NFR-009 asks for exact pins, but exact apt versions go stale within weeks and break builds; the digest fixes the distribution snapshot, and the limit is stated in the README |
| S-47 | Runs as the base image's existing non-root user `ubuntu` (uid 1000); outputs go to a mounted `/out`; the README gives `--user "$(id -u):$(id -g)"` for Docker and `--userns=keep-id` for rootless Podman | `useradd` a new user (fails: uid 1000 exists); run as root | Least privilege, no secrets, and files written to the mounted directory belong to the caller. **The Docker form fails under rootless Podman** (found by running it: `--user` maps to a different host user than the one owning `./out`), hence two documented commands. `MPLCONFIGDIR=/tmp/matplotlib` because a `--user` with no home would otherwise warn |
| S-48 | Only `python/requirements.txt` is copied before the package install, then the rest of the source | `COPY . /app` first | Editing the source no longer repeats the package download. The C++ build, which depends on the source, is still rebuilt (several minutes under rootless Podman) |
| S-49 | The test that an unknown framework is refused configures with the generator of the real build (read from `CMakeCache.txt`) | Name no generator | The first container build **failed here**: with no generator CMake defaulted to Makefiles and `make` is not in the image. A test must not need a tool the build itself does not |
| S-50 | CI builds and runs the image in a `container` job and uploads the outputs, checking the metrics file and that `improvement_ratio` is between 0 and 0.75 | Build the image only on demand | Keeps the clean-room claim true on every push instead of at one moment |
| S-51 | `docs/EVIDENCE.md` holds one row per README claim, quoting it verbatim, with typed evidence (`test:`, `file:`, `req:`, `ci:`, `obs:`) and a strength code (T tested every build, C checked by CI, R recorded observation, I inspection, X external fact). `tests/python/test_evidence_table.py` checks that every quote is still in the README, every README paragraph or bullet has a row, every cited item exists, and a row cannot claim T, C or R without citing that kind of evidence | A prose list of claims; a table nobody checks | VAL-07 asks that every claim has a row and none is unsupported. Unchecked, the table would rot the first time the README changed. Four planted bugs (reworded claim, new unreferenced claim, nonexistent test, stale number) were each caught |
| S-52 | The README's quoted results are checked against fresh runs: the expected-output block, the prose numbers, the velocity claim, the held-out figures, the acceleration figures against `docs/VALIDATION.md`, and the count of Must requirements. Digit checks skip, with the reason, on any compiler other than GCC 13 or Clang 18 | Trust the author to update the numbers | A stale number in a README is exactly the overclaim R-13 describes. The skip reflects a documented platform dependence (the C++ standard leaves the normal distribution unspecified) |
| S-53 | Writing the table meant correcting 12 README statements rather than giving them a flattering row (listed in `docs/EVIDENCE.md`); the `--help` test now checks all 14 flags, their units and defaults, and that each default is accepted; a test was added for a flag with no value, which the coverage report showed had never run | Leave the claims and note the gaps | VAL-07's criterion is "no claim is unsupported". The cheapest honest fix is to change the claim |
| S-54 | CI is hardened without changing what it checks: workflow `permissions: contents: read` (least privilege), a `concurrency` group that cancels a superseded run of the same ref, a `timeout-minutes` on every job (20, container 40), and 30-day artifact retention | Defaults (write-capable token, no timeouts, 90-day artifacts) | A job that only reads the repository should not hold a write token; a hung job should fail in minutes, not hours; 74 artifacts had already accumulated. Checked by parsing the YAML; the first GitHub run confirms it |
| S-55 | `.gitattributes` (`* text=auto eol=lf`, PNG binary), `.editorconfig` (LF, UTF-8, 4 spaces, 2 for YAML, JSON and CMake) and a pull-request template that carries the baseline's definition of done and asks for the evidence-table row | None | A CRLF file once produced a spurious diff and a merge conflict. Renormalizing changes no existing file (checked). The template turns the review habits of M1 to M6 into a checklist |
| S-56 | Repository settings: a description, ten topics, and "delete branch on merge" turned on. The repository stays **private**; no `LICENSE` was added | Make it public; choose a licence | Visibility and licence are the owner's decisions. A scan of tracked files found no secrets, tokens or email addresses; the commit history carries the author email `giba@umich.edu` and one commit the name "Gina Bain", which would become public with it |
